# 更新、打包与构建机验收

使用测试后台和测试设备，入口是“小程序”“APK 打包”“打包机”“应用运营”“系统设置”。部署与接口见 [后台说明](../backend/README.md)，参数见 [APK 打包](PACKAGING.md)。故障演练使用测试频道。

## 小程序发布与回滚

1. 新建测试小程序，用合法 Python 工程名，上传含 `__init__.py` 的 v1，确认版本、文件数和日志。
2. 从 v1 创建启用热更新的测试 APK，保留后台地址、channel、公钥及内部工程名。内部工程名与小程序一致，展示名称可修改。
3. 安装到测试设备并授予权限，运行 v1，记录设备、运行日志和工程版本。
4. 上传并发布 v2，脚本空闲时触发检查或等待既有周期。确认验签及摘要校验后完整替换，下一次运行 v2；运行中的脚本不强行替换。
5. 重新发布 v1，确认设备能回到 v1。这是小程序回滚；APK 本身仍受 Android 签名和版本码规则约束。

故障演练覆盖下载断开、错误摘要、错误清单签名、缺入口 zip、存储不足及更新时脚本运行。预期保留可用工程、记录错误并允许重试，不以清空旧工程处理失败。`ProjectStoreTest` 和更新清单测试覆盖主机可复现部分，存储与 ROM 行为需要设备实测。

## APK 升级

在“应用运营”配置更高版本码、下载地址、摘要与最低版本。核对可选/强制更新、取消安装和下载中断后的表现。系统安装器需要用户确认；同包名升级须同签名，不把卸载清数据当作正常升级方案。

## 本地和远程构建机

分别创建上传 zip、小程序版本两种任务，核对默认展示名称、手动改名、图标、工程名、版本、签名和保护开关。实际安装一个 APK 核对桌面名称及启动入口。

服务端用 `XSCRIPT_PACK_MODE=remote` 启用远程模式，后台添加打包机，在构建机终端使用仅显示一次的令牌：

```powershell
$env:XSCRIPT_WORKER_TOKEN = Read-Host '输入测试打包机令牌'
python -m xscript_server pack-worker --server http://127.0.0.1:8765 --work-dir ./xscript-worker --once
Remove-Item Env:XSCRIPT_WORKER_TOKEN
```

`--once` 处理一项任务，常驻时去掉。跨主机使用实际 HTTPS 地址，构建机安装 JDK、SDK、Python 3.10。

| 场景 | 预期与恢复 |
| --- | --- |
| 正常构建 | 一项任务只被一台领取，日志持续追加，完成后下载正确 APK |
| 构建失败 | 保留原因和日志；修正依赖、参数或编译错误后从后台重试 |
| 排队时取消 | 直接已取消，不再分发 |
| 构建时取消 | 心跳返回取消，构建机停止；迟到产物不覆盖终态 |
| 构建机失联 | 90 秒租约后重排一次，再失联则失败；检查进程和网络后重试 |
| 停用或无证书 | 停用机器不领取；正式签名任务只分给具备签名能力的机器 |
| 后台重启 | 按状态、租约和持有者核对恢复，避免重复分发 |

`test_pack_worker.py` 用本地服务覆盖领取、权限、心跳、日志、产物、取消和租约，构建进程使用受控假构建器，不能代替真实 SDK 与 APK 验证。Windows 跳过的 Unix 进程组测试继续由 Linux CI 验证。

## OSS 分发

系统设置填写测试 Bucket、Endpoint、AccessKey，保存后测试连接。Secret 不回显，留空保存保留原值；查看者不能修改或发起连接测试。环境变量与配置见 [后台说明](../backend/README.md)。

更新接口可返回 OSS 签名 URL 或 CDN 地址，清单仍验签、下载包仍校验 SHA-256。停止 OSS 或模拟上传失败后应回退到 `/pub/bundle/...`。本地 mock 测试不代表访问过真实 Bucket；真实上传、下载和费用在自己的测试账户验收。

记录源码提交、后台版本、APK 摘要和签名指纹、设备型号与系统、结果和未验证项，使用 [交付模板](templates/DELIVERY.md)。
